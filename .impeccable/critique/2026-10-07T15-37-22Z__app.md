## Design Specificity Verdict

**LLM assessment:** Partly authored, not yet unmistakably POPUP.NYC. The warm-white surface, black rules, oversized editorial typography, compact uppercase metadata, and Daily Drop poster treatment create a coherent culture-guide language. Daily Drop’s “Would you show up?” proposition is the most product-specific moment. Explore, however, could still be reused almost unchanged for a generic city guide or fashion magazine: the category controls do nothing, imagery is mostly absent, the first viewport is dominated by a generic question, and specificity comes more from copy than interaction.

**Deterministic scan:** One warning was found: `overused-font` at `app/globals.css:18`, matching `font-family: Arial, Helvetica, sans-serif`. This is an exact match but a low-confidence design defect—the rule does not explicitly name Arial, and a neutral system sans may be intentional. Treat it as a prompt to make the type choice deliberate, not as a correctness failure.

**Visual overlays:** No reliable user-visible overlay is available. Browser inspection and accessibility-state evidence succeeded, but mutable script injection failed because the browser evaluation surface was read-only. No overlay is being claimed.

## Overall Impression

The app looks composed before it feels dependable. Its visual discipline is stronger than many student projects, and the auth and Daily Drop surfaces show a clear point of view. The biggest opportunity is to make the interface earn the trust promised by that polish: current events must actually be current, filters and saving must work, and fictional concepts must remain unmistakably fictional at the artifact level.

## What’s Working

1. **A coherent editorial shell.** Warm white, hairline rules, tight uppercase labels, oversized headlines, and generous spacing repeat consistently across Explore, login, recovery, Saved, Profile, and Daily Drop.
2. **Humane auth recovery.** “Google sign-in was interrupted” avoids blame and gives users clear retry and exit paths.
3. **A focused Daily Drop interaction.** One concept, one short description, and one binary decision keep participation lightweight and aligned with the assignment.

## Priority Issues

### [P1] “Currently in NYC” publishes stale listings

**Why it matters:** A time-sensitive guide loses credibility immediately when events presented as current have already ended. On October 7, 2026, four of the five live listings had ended September 26–27.

**Fix:** Filter expired rows at query time, distinguish happening-now from upcoming, and expose a small verified/updated timestamp.

**Suggested command:** `$impeccable harden`

### [P1] The discovery-to-save loop is promised but not implemented

**Why it matters:** Category buttons look interactive but have no handler or selected state; event cards have no save control; the Saved page remains a static “00.” Users learn that primary controls and benefits are decorative.

**Fix:** Implement URL-backed category filters, add save/unsave on cards with immediate feedback, and render the real saved collection. Until that works, remove any copy promising the feature.

**Suggested command:** `$impeccable shape`

### [P1] Fictional status is detached from the Daily Drop artifact

**Why it matters:** The route introduction says the ideas are fictional, but an individual card names real brands and neighborhoods without a persistent AI/fictional marker. A cropped screenshot can be mistaken for a real event.

**Fix:** Put a compact, persistent “Fictional concept” marker inside every concept card and create a visual distinction from verified event cards without repeating long disclaimers.

**Suggested command:** `$impeccable clarify`

### [P2] Authentication loses the user’s intent

**Why it matters:** `/lab` and `/saved` retain `next`, while `/profile` redirects to generic `/login`. The login page does not say which destination the user is unlocking and does not render `?error=oauth` guidance.

**Fix:** Preserve `next` everywhere, tailor the login heading to the destination, return users there after OAuth, and surface OAuth failure inline.

**Suggested command:** `$impeccable harden`

### [P2] Editorial austerity is suppressing useful signals

**Why it matters:** The hero consumes most of the first viewport, gray image placeholders dominate the event grid, utility text drops to 9–11px, and the nav has no current-route state. Minimalism becomes under-information.

**Fix:** Move a useful weekend/current signal above the fold, raise utility-text size and contrast, add `aria-current`, create an intentional image fallback, and make the type stack a conscious brand decision.

**Suggested command:** `$impeccable layout`

## Persona Red Flags

**Jordan — NYC newcomer planning a weekend:** Jordan clicks a category and nothing changes, then trusts “Currently in NYC” only to discover the event already ended. Missing price, hours, reservation status, and exact location make the guide weak for actual planning.

**Maya — mobile, accessibility-conscious student:** Maya faces horizontally constrained navigation and category rows, tiny uppercase utility text, no active-route cue, low-contrast placeholders, and a six-choice filter strip with no selected state.

**Alex — returning member:** Alex signs in to save events but finds no save action on Explore and a permanently empty Saved page. There is no filter persistence, search, recent history, or calendar shortcut.

**Priya — skeptical of AI misinformation:** Priya encounters a Daily Drop card naming real brands and a real neighborhood without a persistent fictional label. The app’s central trust boundary disappears when the card is isolated or shared.

## Cognitive Load and Emotional Journey

Cognitive load is moderate. The app chunks individual cards and Daily Drop voting well, but the six peer category choices exceed a comfortable immediate decision set and provide no feedback. Auth adds unnecessary memory load because the login page does not carry forward the user’s destination.

The opening creates curiosity and confidence; the emotional valley arrives in the event grid, where stale dates, dead filters, gray placeholders, and no saving turn anticipation into doubt. Daily Drop can be the peak interaction, but its trust boundary needs to travel with the content. The end state of Explore currently feels unfinished because there is no planning or saving payoff.

## Minor Observations

- Explore starts with an `h2` rather than a page-level `h1`.
- Category metadata appears twice on each event card.
- Explore prints raw database error text instead of a recovery-oriented message.
- The Google consent sentence sounds legal but provides no terms or privacy links.
- Avatar copy promises JPG/PNG/WebP while the input accepts every image MIME type and shows no size limit.
- The zero-generation early return can leave `generating` stuck true.
- Real event cards lack a first-party detail view, forcing users off-site for basics.
- Motion has no explicit `prefers-reduced-motion` handling.

## Questions to Consider

- Is POPUP.NYC primarily a beautiful index or a trustworthy weekend-planning tool? The current hierarchy optimizes the former while the product promise requires the latter.
- What if “happening this weekend,” neighborhood, and verified freshness—not the oversized hero—owned the first viewport?
- If a Daily Drop screenshot escaped the page chrome, would anyone know it was fictional?
- What uniquely New York behavior could the interface embody beyond neighborhood names—subway proximity, walk-in likelihood, or “worth crossing town for”?
